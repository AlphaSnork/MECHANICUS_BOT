# 𝙰𝚍𝚎𝚙𝚝𝚞𝚜 𝙼𝚎𝚌𝚑𝚊𝚗𝚒𝚌𝚞𝚜

**Discord-бот Кузни Бога-Машины для ролевых серверов Warhammer 40,000.**
Бот следит за живыми диалогами в выбранных каналах и во время активной беседы вставляет
самодостаточные цитаты из книг WH40k (Ересь Хоруса и Империум 40k), ведёт уровни игроков
(1–100) и валюту «дата-коги», держит магазин, **лутбоксы**, **инвентарь с кнопками**,
**розыгрыши с призами**, приветствует новичков, бросает **кости (d3–d100)**, выдаёт
**роли за реакции**, открывает **тикеты поддержки** и ведёт **аудит сервера**.
Игроки предлагают собственные цитаты через модерацию.

Все команды бота — на русском, с простыми понятными именами: `/цитаты`, `/админы`, `/уровни`,
`/магазин`, `/лутбоксы`, `/розыгрыши`, `/приветствие`, `/выдача`, `/перенос`, `/реакции`,
`/тикеты`, `/аудит`, а также `/ранг`, `/топ`, `/кости`, `/таро`, `/инвентарь`, `/помощь`,
`/аватар`. Внутри разделов путь команды читается как фраза «раздел → объект → действие»:
`/уровни каналы добавить`, `/выдача предметы выдать`.

> Литании подобраны так, чтобы звучать самостоятельно и не требовать контекста книги:
> афоризмы, клятвы, доктрины и хлёсткие реплики персонажей.

## 🚀 Быстрый старт (5 шагов)

1. Создайте приложение и бота в [Discord Developer Portal](https://discord.com/developers/applications)
   (раздел «Bot»), скопируйте **Token**.
2. Пригласите бота на сервер ссылкой вида:
   `https://discord.com/oauth2/authorize?client_id=ВАШ_CLIENT_ID&scope=bot%20applications.commands&permissions=268561616`
   (просмотр каналов, отправка сообщений, вложения и реакции, управление сообщениями,
   **управление ролями** — для ролей за реакции, **управление каналами** — для тикетов,
   **просмотр журнала аудита** — чтобы журнал показывал, кто удалил сообщение)
3. Установите зависимости и положите токен:
   ```bash
   pip install -r requirements.txt
   echo "ВАШ_ТОКЕН" > token.txt        # или переменная окружения DISCORD_TOKEN
   ```
4. Запустите: `python3 bot.py` (Linux/macOS: `./run.sh`, Windows: `start.bat`).
   При первом запуске бот сам установит имя **𝐵𝑙𝑒𝑠𝑠𝑒𝑑 𝐿𝑎𝑑𝑦** и аватар из `avatar.png`.
5. На сервере администратор выполняет:
   ```
   /цитаты включить
   /цитаты каналы добавить channel:#rp-площадка
   ```
   Готово — бот начнёт цитировать во время активных диалогов.

## 1. Подготовка в Discord Developer Portal

1. **Applications → New Application**, название любое (например, `Adeptus Mechanicus RP`).
2. Вкладка **Bot**:
   - Нажмите **Reset Token** и сохраните токен в секрете — он показывается один раз.
   - **Privileged Gateway Intents:** для приветствий новичков включите **Server Members Intent**.
     Если он не включён, бот при запуске сам перезапустится без приветствий — остальной
     функционал (литании, прогрессия, лавка, тех-арки, жребии, аугур) работает без него.
     Message Content Intent боту **не нужен**: содержимое сообщений не читается (приватность).
3. Вкладка **OAuth2 → URL Generator**:
   - Scopes: `bot`, `applications.commands`;
   - Bot Permissions: `View Channels`, `Send Messages`, `Embed Links`, `Read Message History`
     (числовой флаг — `84992`);
   - Скопируйте ссылку и откройте её, чтобы пригласить бота на сервер.
4. Имя и аватар:
   - При первом запуске бот сам установит имя и аватар из `avatar.png`
     (флаг «уже сделано» хранится в `data/state.json`).
   - Если Discord отклонит смену имени через API — задайте имя и аватар вручную на вкладке **Bot**
     или командой `/аватар` (приложив файл).
   - При вступлении на каждый сервер бот ставит себе никнейм `𝐵𝑙𝑒𝑠𝑠𝑒𝑑 𝐿𝑎𝑑𝑦`.

## 2. Установка и запуск

Требования: **Python 3.10+**.

```bash
pip install -r requirements.txt
echo "ВАШ_ТОКЕН" > token.txt     # либо: export DISCORD_TOKEN="ВАШ_ТОКЕН"
python3 bot.py                   # ./run.sh | start.bat
```

**Работа в фоне (VPS):** `nohup python3 bot.py > lexveritas.log 2>&1 &` или systemd/screen/tmux.
**Самопроверка без Discord:** `python3 bot.py --selftest`.

### Хостинг bot-hosting.net

Весь код бота — один файл `bot.py` (ядро деплоя); дополнительных модулей не требуется.

1. Загрузите в **корень** деплоя: `bot.py`, `requirements.txt`, `avatar.png`, папку `data/`
   (вкладка Files, SFTP или ZIP-архив с последующей распаковкой в корень).
2. Вкладка **Startup**: Entry File (`STARTUP_FILE`) = `bot.py`.
3. Зависимости устанавливать вручную не нужно: деплой сам читает `requirements.txt` при старте.
4. Токен задайте во вкладке **Env Variables** переменной `DISCORD_TOKEN`
   (файл `token.txt` тоже поддерживается, но переменная окружения безопаснее).
   При старте бот пишет в консоль, откуда взят токен; при отклонённом токене
   (LoginFailure) в консоль выводится понятная подсказка.
5. В Developer Portal (Bot → Privileged Gateway Intents) включите **Server Members Intent**
   для приветствий; без него бот при запуске сам перезапустится без приветствий.
6. Данные живут в `data/` и сохраняются между перезапусками; панель делает ежедневные
   снапшоты, но держите собственную копию `data/` вне хостинга. При падении деплой
   перезапускает бота автоматически.

### Веб-дашборд настройки (панель Адептус Механикус)

В бот встроен веб-сайт настройки: тот же процесс, те же данные `data/`, изменения
применяются мгновенно без перезапуска. Включается тремя шагами:

1. **Developer Portal → ваше приложение → OAuth2 → Redirects:** добавьте
   `<ваш DASHBOARD_URL>/callback` (например, `http://ВАШ_IP:8080/callback`).
   Там же скопируйте **Client Secret**.
2. **Хостинг → Env Variables:** задайте
   `DISCORD_CLIENT_SECRET` (секрет из шага 1),
   `DASHBOARD_URL` — публичный адрес панели **без** `/callback` (бот дописывает его сам),
   например `http://fi12.bot-hosting.cloud:25403`;
   при желании `DASHBOARD_SECRET` (ключ подписи сессий, тип Secret).
   `DASHBOARD_PORT` на bot-hosting.net задавать **не нужно**: бесплатный тариф открывает
   только Primary-порт `SERVER_PORT`, и панель по умолчанию слушает именно его
   (явно заданный `DASHBOARD_PORT` имеет приоритет, если у вас платный план и свой порт).
3. **Хостинг → Network:** на бесплатном тарифе отдельный порт открыть нельзя —
   используйте уже открытый Primary (`Exposed ports` → адрес вида `хост:порт`);
   это и есть `DASHBOARD_URL`. Перезапустите бота: в консоли появится
   «Дашборд запущен: …». Без `DISCORD_CLIENT_SECRET` дашборд отключён, бот работает как раньше.

Оформление (сборка r19, тематика «Адептус Механикус»: красный бархат и металл — ганметал,
латунь, сигильные шестерни): верхняя навигационная полоса с эмблемой кузни
(`web/avatar.png`) и разделами; главная — hero-блок «Кузница Адептус Механикус»
с рамой-изображением и волной, ниже сетка карточек разделов; каждый раздел — отдельная
«капсула» с шапкой и оформленным артом в рамке (`img.cap-art`, не фон страницы):
`web/art_forge.jpg`, `art_litany.jpg`, `art_cog.jpg`, `art_ark.jpg`, `art_conclave.jpg`,
`art_data.jpg`. Шрифты — Orbitron и Rajdhani (Google Fonts; без интернета браузер падает
на sans-фолбэк). Папку `web/` загружайте вместе с `bot.py`; если её нет — панель просто
останется без артов, ничего не ломается.

Интерфейс: навбар без отдельной панели вкладок (промежуток устранён); внутри капсулы —
широкий трёхколоночный макет: слева сводка сервера (участники, боты, роли, каналы), справа
крупная случайная цитата архива с кнопкой «⚙ Другое слово», снизу журнал действий
(аудит: слэш-команды, нажатия кнопок и правки из панели; кольцо на 200 записей, файл
`data/audit.json`). Вкладка «Книга литаний» содержит полный
архив (канон + архив сервера) с поиском, пагинацией, модерацией и формой добавления цитат;
во вкладке «Ранги познания» настраиваются награды за ранги (роль / предмет / дата-коги),
в «Жребиях» — тип призов: предметы в кладезь или валюта на баланс.
Посвящения требуют Server Members Intent (запрашивается по умолчанию; отключение —
`INTENTS_MEMBERS=0`). Запуск всегда однократный: никаких повторных `bot.run()`.

Вход — кнопка **«Войти через Discord»** (OAuth2, scope `identify guilds`). Видны только
серверы, где вошедший — администратор бота (логика зеркалит `/админы список`:
список админов → владелец сервера → право «Управление сервером»). Вкладки:
**Кузница, Книга литаний, Ранги познания, Лавка кузни, Тех-арки, Жребий конклава,
Ритуал посвящения, Магосы кузни, Передача данных, Роли за реакции, Тикеты, Аудит кузни** —
все настройки тех же модулей, что и в слэш-командах, с живыми списками каналов и ролей
из кэша бота и модерацией цитат кнопками. Разделы «Роли за реакции», «Тикеты» и
«Аудит кузни» настраивают модули r18 (панели эмодзи, панель поддержки, журнал событий
и отчёт безопасности) прямо в браузере — без единой команды.

Безопасность: сессия — подписанная HttpOnly-cookie (12 часов), все POST-формы защищены
CSRF-токеном, чужие серверы и пользователи без прав получают отказ. Если есть возможность,
держите панель за HTTPS (домен/прокси): cookie передаются по HTTP.

## 3. Кто может настраивать бота

- `/админы список` — кто сейчас администраторы бота;
- `/админы добавить user:@ник` — назначить администратора бота;
- `/админы убрать user:@ник` — снять администратора.

Пока список пуст, настраивать могут владелец сервера и обладатели права «Управление сервером».
Как только в списке появился хоть один человек — настраивают **только** люди из списка
(плюс владелец приложения-бота — страховка от блокировки).

## 4. Цитаты во время диалогов

| Команда | Что делает |
|---|---|
| `/цитаты включить` / `/цитаты выключить` | Включить / выключить литании на сервере |
| `/цитаты каналы добавить channel:#канал` | Добавить канал публикации цитат (можно несколько) |
| `/цитаты каналы убрать channel:#канал` | Убрать канал |
| `/цитаты каналы список` | Список каналов публикации |
| `/цитаты интервал interval:45 window:10 min_messages:6 min_users:2` | Частота и критерии активности |
| `/цитаты эпоха era:<выбор>` | Фильтр эпох: Все / Ересь Хоруса / Империум (40k) |
| `/цитаты режим mode:<выбор>` | Литании игроков: модерация / авто / отключены |
| `/цитаты настройки` | Все текущие настройки бота на сервере |

Параметры частоты: `interval` — пауза между литаниями в канале (5–10080 мин, по умолчанию 45);
`window` — окно анализа (1–120 мин, по умолчанию 10); `min_messages` (2–200, по умолчанию 6);
`min_users` (2–100, по умолчанию 2). Каждые 20 секунд бот проверяет каналы: если за окно набралось
достаточно сообщений от достаточного числа авторов — диалог живой, и бот отправляет цитату
(пауза `interval` + случайные 0–4 минуты). Боты и вебхуки не учитываются.

## 5. Уровни игроков

Сообщения в каналах прогрессии приносят XP и дата-коги (с кулдауном от накрутки).
Дата-коги за сообщение = база × множитель ранга × коэффициент роли.
Требуемый XP для повышения = `xp_base × ранг^xp_growth` (по умолчанию 100 × ранг^1.5).

| Команда (администраторы) | Что делает |
|---|---|
| `/уровни каналы добавить channel:#канал • /уровни каналы убрать channel:#канал` | Каналы прогрессии |
| `/уровни каналы список` | Список каналов прогрессии |
| `/уровни настройки xp:10 credits:5 cooldown:60 xp_base:100 xp_growth:1.5` | Ставки и кривая рангов |
| `/уровни таблица` | Таблица требуемого XP для рангов 1–100 |
| `/уровни множители задать level:5 value:2` | Множитель дата-когов для ранга |
| `/уровни множители таблица действие:<Показать|Сбросить>` | Таблица множителей / сброс (×1, ×1.1, ×1.3, ×1.6, …) |
| `/уровни роли добавить role:@роль value:1.25 apply:<…> • /уровни роли убрать role:@роль` | Коэффициент роли (Опыт и валюта / Только валюта / Только опыт); при нескольких ролях действует наибольший |
| `/уровни роли список` | Список ролевых коэффициентов |
| `/уровни награды добавить level:5 kind:<Роль|Предмет в инвентарь|Валюта> role:@роль name:«…» amount:100` | Награда за достижение ранга (роль / предмет в кладезь / дата-коги на баланс) |
| `/уровни награды список` • `/уровни награды убрать reward_id:№` | Список и удаление наград |
| `/уровни анонсы` | Анонс повышения ранга в канале |
| `/уровни сброс игрока user:@игрок` | Сброс прогресса одного игрока |
| `/уровни сброс всех confirm:True` | Сброс прогресса всего сервера (необратимо!) |

Игроки: `/ранг [user]` — карточка (ранг познания, шкала прогресса, дата-коги, множитель, место в реестре);
`/топ` — топ-10 сервера по уровню.

## 6. Магазин и инвентарь

| Команда | Кто | Что делает |
|---|---|---|
| `/магазин добавить name:«Товар» price:150 description:«…»` | админ | Добавить товар |
| `/магазин убрать item:№` | админ | Убрать товар |
| `/магазин уведомления channel:#канал role:@роль` | админ | Куда пинговать о покупках и использовании предметов |
| `/магазин список` | все | Витрина с **кнопками покупки** и листанием страниц |
| `/магазин купить item:№` | все | Купить товар (дата-коги списываются сразу) |
| `/инвентарь [user]` | все | **Кладезь с кнопками**: страницы ◀ ▶, выбор предмета, «Использовать предмет» / «Назад» |

Купленный товар попадает в кладезь игрока. В инвентаре предмет можно выбрать кнопкой и нажать
«Использовать предмет» — бот напишет стилизованное сообщение и пинганёт роль уведомлений лавки
в настроенном канале (`/магазин уведомления`), чтобы предмет выдали в игре; сам предмет при этом
расходуется.

## 13. Кости, роли за реакции, тикеты, аудит (новое в r18)

**Кости** — `/кости dice:d20 count:3 modifier:1`: бросок одной или нескольких костей
(d3, d4, d5, d6, d8, d10, d20, d100), до 20 штук за раз, с необязательным модификатором.
Результат виден всему каналу — удобно для игровых проверок.

**Роли за реакции** (как Carl-bot):

1. `/реакции панель channel:#канал title:Заголовок` — бот опубликует сообщение-панель;
2. `/реакции добавить panel_id:1 role:@роль emoji:🔥 label:Описание` — связать эмодзи с ролью
   (бот сам поставит реакцию и обновит список ролей на панели);
3. Игрок нажимает эмодзи — получает роль; снимает реакцию — роль убирается.

`/реакции список` — все панели; `/реакции убрать` — снять роль с панели; `/реакции удалить` —
удалить панель целиком. Боту нужно право «Управление ролями»; роль должна стоять ниже роли бота.
Тихих отказов нет (r21): если роль выдать нельзя (роль выше роли бота, управляется интеграцией,
боту не хватает «Управления ролями», сбой API) — бот снимает реакцию и объясняет причину
участнику в личные сообщения, а запись уходит в журнал консоли. Участник при этом может быть
вне кэша (интент members выключен) — бот добирает его через API.
`/реакции проверка` — диагностика и починка «почему не выдаётся» (r22): сборка бота, право
«Управление ролями», интент участников, верхняя роль бота и по каждой панели: канал,
сообщение, можно ли выдать каждую роль (иерархия, интеграция); потерянные реакции под
панелями бот автоматически ставит заново.
`/реакции тест panel_id:1 role:@роль` — живая проверка (r22): бот выдаст роль вам и тут же
снимет, а при отказе назовёт точную причину (иерархия, права, интеграция).
Сопоставление эмодзи устойчивое (r22): кастомные эмодзи сравниваются по id (переименование
эмодзи больше не рвёт панели), юникод — без учёта вариатора U+FE0F («▶» и «▶️» — одна
кнопка), а в `emoji:` можно вписать имя эмодзи сервера (pepe) вместо `<:имя:id>`. Отказ
выдачи пишется ещё и в журнал аудита (группа «Сервер») — его видно даже при закрытых ЛС
участника; клик по эмодзи, не привязанному к роли, отмечается в логе хостинга.
Панели с сайта и из команд хранятся в одном файле (`data/reaction_roles.json`) и с r23
лечатся одинаково: «мёртвые» записи, которые старые версии сайта сохраняли словом вместо
эмодзи («pepe» вместо `<:pepe:id>` — панель создавалась, реакция не ставилась, роль не
выдавалась), автоматически переписываются в настоящий эмодзи при старте бота, при
открытии вкладки «Роли за реакции», в `/реакции проверка` и даже в момент клика игрока
по панели. Пересоздавать панели не нужно.

**Тикеты** (как Ticket Tool):

1. `/тикеты настройки category:Тикеты support:@Поддержка log_channel:#логи` — один раз;
2. `/тикеты панель channel:#поддержка` — сообщение с кнопкой «📩 Создать тикет»;
3. Игрок нажимает кнопку — создаётся приватный канал (виден только автору, роли поддержки и боту);
4. `/тикеты закрыть [reason]` или кнопка «🔒 Закрыть тикет» — канал удаляется, в лог-канал
   уходит карточка (автор, кто закрыл, причина) и файл-транскрипт всей переписки;
5. `/тикеты добавить user:@игрок` — впустить в тикет ещё одного участника.

Боту нужно право «Управление каналами». Один игрок — один открытый тикет; кнопки переживают
перезапуск бота. Публичного оповещения «тикет создан» в канале панели нет (r21): приветствие
с пингом автора и поддержки пишется только внутрь самого тикета.

**Аудит сервера**:

- `/аудит настройки channel:#журнал members:Включить messages:Включить server:Включить` —
  журнал событий в канал: вход/выход (возраст аккаунта, метка «возможен рейд»), баны и разбаны,
  удаление сообщений (автор, текст и **кто удалил**; массовые очистки — одной записью),
  правка сообщений, выдача/снятие ролей, смена ников, создание/удаление каналов и ролей,
  изменения прав ролей, приглашения.
- `/аудит отчёт` — сводка безопасности с оценкой 0–100: 2FA для модерации, уровень проверки
  участников, фильтр содержимого, права @everyone, число админ-ролей и ботов + рекомендации.

Кэш последних 100 сообщений канала сохраняется на диск (`data/msg_cache.json`) и переживает
перезапуск бота: текст удалённого сообщения виден, даже если оно отправлено до рестарта.
Сам текст пишется при `INTENTS_CONTENT=1`; без него в журнале остаются автор, канал и факт
события. Строка «кто удалил» берётся из журнала аудита Discord — для неё боту нужно право
«Просмотр журнала аудита» (ссылка приглашения выше его уже включает).

## 15. Данные, резервные копии

Все данные лежат в папке `data/` рядом с ботом: настройки серверов, литании, прогресс, лавка,
тех-арки, инвентари, жребии, состояние. Для переноса бота на другой хост скопируйте всю папку
проекта. Не запускайте бота одновременно в двух местах с одним токеном.

Каноническую базу можно расширять вручную: отредактируйте `data/quotes_canon.json` и перезапустите
бота. Формат записи:
```json
{"text": "Текст цитаты.", "author": "Автор", "source": "«Название книги» (Автор книги)", "era": "heresy"}
```
где `era` — одно из: `heresy`, `imperium`, `both`. Литания должна быть самодостаточной и длиной до ~300 символов.

## 16. Частые проблемы и решения

| Симптом | Решение |
|---|---|
| Слэш-команды не видны | Бот приглашён без scope `applications.commands`; синхронизация команд занимает до нескольких минут |
| Бот включён, но молчит | `/цитаты настройки`: есть ли каналы; идёт ли живой диалог; не велика ли пауза; есть ли право «Встраивание ссылок» |
| Посвящения не работают | Включите Server Members Intent в Portal (бот при запуске сам подскажет и перезапустится без них) |
| Кнопки меню не нажимаются | Меню живёт 5 минут и принадлежит открывшему: откройте заново своей командой |
| Кнопка жребия не работает после перезапуска | Не бывает: кнопки жребиев персистентные; если жребий завершён — кнопка снята |
| Пинг роли уведомлений не приходит при покупке/использовании предмета | Настройте `/магазин уведомления channel:… role:…` |
| «Недостаточно прав» у администратора | Нужен статус администратора бота (`/админы добавить`) или право «Управление сервером», пока список пуст |
| Токен утёк | Reset Token в портале, обновите `token.txt`, перезапустите бота |
| Панель, созданная на сайте, не выдаёт роли (через команды всё работает) | Обновите бота (r23+) и откройте вкладку «Роли за реакции»: «мёртвые» записи эмодзи старых версий сайта исцеляются автоматически; диагностика — `/реакции проверка` |

## 17. Примечания

- **Приватность:** бот работает без Message Content Intent — содержимое сообщений не читается
  и не сохраняется; учитываются только время сообщения и его автор.
- **Литании:** приведены в распространённых фан-переводах и адаптациях; короткие литании используются
  в ознакомительных целях для ролевой игры.
- **Кнопки:** все интерактивные меню (кладезь, лавка, модерация, тех-арки, справка, аугур)
  защищены от чужих нажатий и сами гаснут по таймауту; кнопки жребиев — персистентные.

## 18. Перенос ролевых сообщений между серверами (вебхуки)

Гибридная схема по исследовательскому отчёту: бот читает историю исходного сервера
и пишет её в целевой канал через вебхук **с именем и аватаром оригинального автора** —
включая персонажей Tupperbox/PluralKit (у прокси-сообщений имя/аватар берутся из `author`).

Подготовка (три шага, все подсказки есть во вкладке «Перенос»):
1. Пригласите бота на исходный сервер ссылкой из вкладки «Перенос»
   (права: Administrator, флаг 8 — гарантированный доступ ко всем каналам, включая закрытые).
2. Включите **Message Content Intent** в портале (Bot → Privileged Gateway Intents)
   и задайте Env `INTENTS_CONTENT=1`, затем Restart. Без этого Discord не отдаёт текст
   сообщений ни в_gateway, ни в REST — задача не стартует с понятной подсказкой.
   По умолчанию intent выключен: приватность игроков прежняя, перенос — opt-in.
3. Создайте задачу во вкладке «Перенос»: исходный сервер и канал, целевой канал,
   режим (история / зеркалирование / оба), глубина истории (сколько последних сообщений
переносить из каждого канала/публикации: по умолчанию 100, 0 — вся история),
вложения и embeds — галочками.
   Вебхук создастся сам (нужно Manage Webhooks в целевом канале) или вставьте готовый URL.

Управление: кнопки «▶ Запустить / ⏸ Стоп / 🗑» на сайте и `/перенос список|статус|старт|стоп|удалить`.
Ограничения и поведение: системные сообщения пропускаются; текст режется до 2000 символов,
имя до 80; вложения до 10 шт. и 25 МБ; embeds до 10; пинги отключены (`allowed_mentions: parse=[]`);
темп отправки ~0.4 с/сообщение с ретраями на 429; прогресс (перенесено/ошибки) виден в таблице;
прерванную задачу можно возобновить — история продолжится с курсора последнего сообщения;
задачи в статусе «running» автоматически возобновляются после рестарта бота.
Источником и целью могут быть **форумы**: задача переносит все их публикации (активные и архивные),
на цели публикации воссоздаются — в форуме-цели через `thread_name`, в текстовом канале-цели
как ветки; соответствие «исходная публикация → целевая ветка» хранится в `thread_map` задачи,
поэтому зеркалирование новых постов продолжает уже созданные ветки. Отдельную ветку тоже
можно выбрать источником. Публикации собираются из трёх источников (кэш гейтвея,
архивные треды и REST-список активных тредов), поэтому не теряются даже при пустом кэше;
кнопка «🔍 Проверить видимость источника» в форме задачи показывает, сколько публикаций/
сообщений бот реально видит в выбранном источнике. Публикации форума можно отбирать
чекбоксами (заброшенные/пустые — пропускать); ничего не отмечено = весь форум. Оригинальные таймстампы сообщений Discord через вебхуки не принимает —
сохраняются порядок, авторство и содержимое.
